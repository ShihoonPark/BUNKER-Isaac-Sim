# BUNKER Isaac Sim

Isaac Sim based simulation, trajectory planning, and control project for the AgileX BUNKER MINI 2.0 tracked robot.

- Ubuntu 22.04.5 LTS
- NVIDIA GeForce RTX 3080 10GB
- NVIDIA Driver 580.173.02
- NVIDIA Isaac Sim 5.1.0
- ROS 2 Humble

## External BUNKER Asset

The AgileX simulation repository is not committed to this repository. Clone it under `assets/` when needed:

~~~bash
cd assets
git clone https://github.com/agilexrobotics/ugv_gazebo_sim.git
~~~

`assets/ugv_gazebo_sim/` is an ignored external source clone. `assets/bunker_mini_imported/` is generated by the Isaac Sim importer and is also ignored.

The local inspection stages `scenes/bunker_import_inspection.usd` and `scenes/tracked_force_plant_v2_flat_box_inspection.usd` are ignored because they reference the generated importer asset at `../assets/bunker_mini_imported/bunker_mini/bunker_mini.usd`. Reproducible plant construction therefore lives in the tracked JSON configuration and Python build/model/test scripts rather than depending on those local USD files.

## Tracked-Plant Development

### V1: driven-roller prototype

V1 uses multiple driven cylindrical rollers and revolute joints. It was useful for initial tracked-motion and command-sign experiments, but exposed undesirable solver/constraint-authoring-order sensitivity and poor skid-turn behavior under native isotropic contact friction. V1 remains in the repository as an experimental prototype and failure-analysis reference; it is not the recommended plant.

### V2: directional-force plant

V2 is a single floating BUNKER rigid body without track articulation or hundreds of belt links. PhysX handles rigid-body motion, gravity, collision, normal support, and the resulting pitch, roll, and Z dynamics. Longitudinal propulsion and lateral skid resistance are instead applied as explicit forces at reported physical contacts.

The high-level interface remains body linear and angular velocity, `v_cmd` and `omega_cmd`. With the measured track-center spacing `B = 0.434 m`, commands map to virtual track surface speeds as:

~~~text
v_left  = v_cmd - (B / 2) * omega_cmd
v_right = v_cmd + (B / 2) * omega_cmd
~~~

For each physical contact, the controller projects the vehicle-forward direction into that contact's tangent plane and constructs a matching lateral tangent consistent with vehicle +Y left. Longitudinal and lateral forces are resolved and applied in this contact-tangent basis, not merely in the body XY plane. The measured custom-force normal component is approximately numerical zero, preventing artificial vertical force when the body or contact surface is tilted.

### Flat-track support baseline

The default V2 support mode is `flat_track_boxes`: one continuous, invisible, fixed compound box collider per track. The measured support footprint is:

- Length: `0.440224 m`
- Width: `0.100000 m`
- Center X: approximately `-0.009545 m`
- Center Y: `+0.217000 m` left and `-0.217000 m` right

The box thickness is `0.020 m`. This is an uncalibrated numerical support assumption, not a measured physical track thickness. The earlier support geometry remains selectable as `cylinders_legacy` for comparison. In either mode, the five measured X patch locations are virtual contact-classification and force-distribution bins; they are not five independently driven bodies or claims about physical wheel count.

### Current simulator baseline

These results validate the current simulator structure; they are not a real-robot calibration or evidence of simulator–real equivalence.

- Straight: `dx = +1.080243 m`, `dy = +0.020669 m`, `dyaw = +0.034884 rad`; no side-support loss, final roll approximately zero, and maximum vertical velocity approximately `0.000115 m/s`.
- Positive in-place: `dyaw = +1.392377 rad`, translation magnitude approximately `0.0388 m`; correct positive yaw sign and no side-support loss.
- Full suite: `straight`, `left_only`, `right_only`, `positive_in_place`, `negative_in_place`, `positive_curve`, and `negative_curve` passed. Authoring-order invariance passed with zero final-pose difference.

V2 is an uncalibrated but structurally stable Isaac Sim tracked-plant baseline. Actuator lag, longitudinal traction, lateral skid/friction, force limits, and left/right bias must later be calibrated from measurements of the real BUNKER.

## Run the V2 Plant

Run the full headless suite with the default flat support explicitly selected:

~~~bash
env -u PYTHONPATH -u LD_LIBRARY_PATH -u ROS_DISTRO -u AMENT_PREFIX_PATH -u CMAKE_PREFIX_PATH \
  /home/a/isaacsim/python.sh scripts/test_tracked_force_plant_v2.py \
  --support-mode flat_track_boxes
~~~

Run one straight case interactively, without the additional authoring-order comparison:

~~~bash
env -u PYTHONPATH -u LD_LIBRARY_PATH -u ROS_DISTRO -u AMENT_PREFIX_PATH -u CMAKE_PREFIX_PATH \
  /home/a/isaacsim/python.sh scripts/test_tracked_force_plant_v2.py \
  --case straight --support-mode flat_track_boxes --skip-order-invariance --gui --realtime
~~~

## Launch Isaac Sim

~~~bash
./scripts/run_isaac.sh
~~~

## Notes

- Large ROS bags, point clouds, logs, downloaded external repositories, and generated Isaac Sim imports are excluded from Git.
- The imported BUNKER URDF contains a single rigid `base_link`; the V2 build script creates the derived tracked-plant representation without modifying the generated import.
